# LCAgent 使用说明

本文说明如何使用 LCAgent 桌面客户端、配置大模型与 Embedding、连接 Unreal Engine、建立知识库和资源注册表，以及运行智能体任务。

安装依赖和首次启动命令请先阅读根目录的 [README](../README.md)。

## 1. 界面分工

当前版本有两个本地界面，二者共用同一套 Python 后端数据：

| 界面 | 用途 | 当前可用功能 |
|---|---|---|
| Electron 桌面客户端 | 日常主入口 | 工作区添加/移除、模型选择、对话与上下文管理、UE 资源读取、知识库上传与检索 |
| Streamlit 管理控制台 | 配置与管理 | 新增模型和 Embedding、资源语义报告审核、智能体任务、诊断 |

LCAgent 是本地应用，不需要填写 Email，也不需要创建 LCAgent 账号。模型 API Key 由用户自行配置并只保存在本机。

Electron 中的“任务”和“设置”入口仍在迁移。UE 资源读取与知识库日常使用已经进入桌面端；模型配置、Embedding 配置和资源文件夹用途报告审核仍由 Streamlit 完成。

## 2. 推荐启动顺序

### 2.1 需要连接 UE 时

1. 使用 Visual Studio 2022 编译 UE 工程和插件；
2. 打开目标 UE 工程，等待编辑器和 UnrealMCP 完全启动；
3. 启动 Electron 客户端；
4. 在客户端中打开工作区并检查 UE 状态；
5. 需要修改模型、Embedding、审核资源语义报告或运行智能体任务时，再启动 Streamlit 管理控制台。

### 2.2 只进行离线工作时

如果只进行模型对话、知识库配置、JSON 生成或离线测试，可以不启动 UE。客户端会显示 UE“未连接”，其他离线功能仍可使用。

### 2.3 启动 Electron

```powershell
cd E:\LCAgent\desktop
npx --yes pnpm@11.19.0 dev
```

Electron 会自动启动 Python 服务，无需再单独运行 `LCA/service.py`。启动终端需要保持打开。

### 2.4 启动管理控制台

新开一个 PowerShell 窗口：

```powershell
cd E:\LCAgent
.\langchain_env\Scripts\python.exe -m streamlit run LCA\frontend_app.py --server.address localhost --browser.gatherUsageStats false
```

访问 `http://localhost:8501`。使用 `run_frontend.ps1` 启动时，运行日志保存在 `E:\LCAgent\streamlit.log`。

## 3. 打开工作区

工作区是 LCAgent 保存对话、知识库、资源报告和任务上下文的逻辑范围。一般建议把目标 UE 工程根目录设为工作区，例如：

```text
E:\UE_project\LandscapeTool
```

### 3.1 Electron 客户端

1. 在左侧工作区区域选择已有工作区；
2. 第一次使用时，输入本地绝对路径并打开；
3. 确认顶部或状态区域显示正确的工作区名称；
4. 不同工作区的对话上下文会分别保存。

工作区条目右侧的“×”用于移除工作区入口。该操作不会删除磁盘上的 UE 工程、知识库或历史数据；以后重新添加相同路径时，工作区 ID 不变，原有数据仍可继续使用。

当前版本的 Electron 尚未接入原生文件夹选择器，需要输入或粘贴路径。路径必须真实存在。

### 3.2 Streamlit 管理控制台

1. 展开侧边栏“添加工作区”；
2. 可点击“浏览本机文件夹”，也可手工填写绝对路径；
3. 添加后，从侧边栏“工作区”下拉框选择目标工程。

不要把同一工程以不同拼写重复加入，例如不要同时添加带尾部反斜杠和不带尾部反斜杠的路径。

## 4. 配置决策/对话大模型

决策模型同时负责工作区对话、任务规划和代码生成。系统不再维护单独的“执行智能体大模型”；校验、知识检索和 UE 调用由确定性工具完成。

目前新增或编辑模型需要在 Streamlit 的“模型”页完成。

### 4.1 新建模型档案

1. 打开“模型”页；
2. 在“编辑档案”中选择“新建模型”；
3. 填写以下信息：

| 字段 | 说明 |
|---|---|
| Profile ID | 本地唯一标识，例如 `deepseek-main`；保存后不可修改 |
| 显示名称 | 在 Electron 和管理控制台中显示的名称 |
| 提供商 | `deepseek`、`openai` 或 `openai_compatible` |
| Base URL | 模型服务 API 根地址 |
| API Key | 真实密钥，只写入本机 `LCA/.env` |
| API Key 环境变量 | 密钥在 `.env` 中使用的变量名 |
| 模型名称 | 服务端公布的模型 ID，不是自定义昵称 |
| Temperature | 场景构建与代码生成建议从 `0` 开始 |
| 超时/重试 | 根据网络与模型响应速度设置 |

DeepSeek 常见 Base URL 示例为：

```text
https://api.deepseek.com
```

OpenAI 官方服务通常使用：

```text
https://api.openai.com/v1
```

其他兼容 OpenAI API 的服务请选择 `openai_compatible`，Base URL 是否需要包含 `/v1` 以服务商文档为准。

### 4.2 自动获取模型列表

填写 Base URL 和 API Key 后，点击“自动获取模型列表”。LCAgent 会调用服务端模型列表接口，并把返回的模型放入下拉菜单。

如果厂商不支持模型列表接口、接口路径不同或密钥权限不足，自动获取可能失败。此时可根据厂商文档手工填写模型 ID，不影响保存档案。

### 4.3 上下文设置

- “上下文窗口”应填写模型官方公布的 Token 上限；不确定时可暂时保留 `64000`。
- “自动压缩阈值”表示估算上下文达到窗口多少比例时触发压缩，默认思路为 65%。
- “保留最近对话轮数”决定压缩后仍原样保留多少轮最近消息，建议从 6 轮开始。

系统压缩时会让当前决策模型生成结构化摘要，并保留近期原始对话。摘要中包含目标、约束、已确认决定、未解决问题和关键路径，后续调用会使用“摘要 + 最近对话 + 当前消息”。

### 4.4 保存与测试

1. 勾选“设为默认模型”；
2. 点击“保存模型”；
3. 重新选择该档案；
4. 点击“测试连接”；
5. 测试成功后回到 Electron，模型应出现在下拉菜单中。

如果 Electron 已经打开但没有显示新模型，刷新客户端或重新启动 Electron。

> Embedding 模型不能作为对话模型使用。Electron 的模型下拉框中应选择能完成聊天或代码生成的模型。

## 5. 配置 Embedding 模型

Embedding 只负责把文档切片和查询转换成向量，不参与对话、规划或代码生成。它与决策模型必须分别配置。

在 Streamlit“模型”页下方找到“Embedding 模型”：

1. 选择“新建 Embedding”；
2. 填写 Profile ID、显示名称、提供商和 Base URL；
3. 填写厂商提供的 Embedding 模型 ID；
4. 填写 API Key 和对应环境变量名；
5. 向量维度不确定时保留 `0`，由模型决定；
6. 将其设为默认 Embedding 并保存；
7. 点击“测试 Embedding”，确认能够返回非空向量和正确维度。

系统目前支持 OpenAI 和 OpenAI-compatible Embedding 接口。部分厂商的聊天 API 兼容 OpenAI，但 Embedding API 不兼容，必须以实际接口测试结果为准。

## 6. 连接 Unreal Engine

### 6.1 插件位置与编译

当前可编辑 UE 插件仓库是：

```text
E:\UE_project\LandscapeTool\Plugins
```

远程仓库为 [LandscapeTool-Plugins](https://github.com/yxy123123123123/LandscapeTool-Plugins)。`E:\LCAgent\UnrealMCP-master` 是历史对照副本，不再修改。

编译步骤：

1. 关闭 UE 编辑器；
2. 使用 Visual Studio 2022 打开 UE 工程 `.sln`；
3. 编译目标工程的 Editor 配置；
4. 启动 UE；
5. 在插件管理页面确认 UnrealMCP 和本次任务依赖的 Landscaping、RoadAuto、RiverAuto 等插件已启用；
6. 如刚启用插件，重启 UE。

### 6.2 连接检测

UnrealMCP 默认监听：

```text
Host: 127.0.0.1
Port: 13377
```

在 Electron 中点击 UE 连接/刷新按钮，或在 Streamlit“工具”页点击“测试 UE 连接”。成功时应显示类似：

```text
UE 连接正常：工程 LandscapeTool，契约 v1，能力 13 项
```

这表示：

- TCP 已连通；
- UnrealMCP 支持当前握手协议；
- Python 侧已得到 UE 工程身份和能力清单。

能力数量可能随插件版本变化，不应固定要求必须等于 13；重点是握手成功且所需能力存在。

### 6.3 常见连接错误

**显示 `Unknown command: Status`**

这是旧客户端向插件发送了不受支持的 `Status` 命令。当前版本已改用协议握手。确认正在运行最新 LCAgent Python 服务和最新 UnrealMCP 插件，并重启 Electron 与 UE。

**显示连接被拒绝或超时**

- 确认 UE 已完全启动，而不只是停留在工程选择器；
- 确认 UnrealMCP 插件已启用；
- 查看 UE Output Log 中是否出现插件启动或端口监听错误；
- 检查本机防火墙是否阻止 `127.0.0.1:13377`；
- 确认没有另一个 UE 实例占用相同端口。

**握手成功但某项工具不可用**

握手成功只说明通信主链路正常。还需要确认 Landscaping、RoadAuto、RiverAuto 等具体插件已经编译、加载，且握手能力列表包含目标操作。

## 7. 建立 UE 资源注册表

资源注册表用于避免模型猜测 `/Game/...` 资源路径。它不是向量库，而是由 UE 权威扫描、模型进行文件夹语义分析、用户最终批准的结构化工程数据。

资源扫描必须在 UE 打开且 UnrealMCP 已连接时进行，因为只有 UE Asset Registry 能可靠给出资产对象路径、类型和工程状态。

### 7.1 在 Electron 中读取资源

1. 打开 UE 工程并确认右侧“UE 连接”显示已连接；
2. 打开 Electron 左侧“UE 资源”；
3. 在“扫描包路径”填写 `/Game`，也可以用逗号分隔多个包路径；
4. 点击“读取 / 更新 UE 资源”；
5. 查看文件夹统计、资产类型和真实对象路径；
6. 使用筛选框按对象路径或资产类型检查结果。

扫描结果会直接写入当前工作区资源注册表。这个步骤只读取 UE 的权威数据，不调用大模型，也不会修改 UE 资产。

### 7.2 生成并审核语义报告

1. 在 Streamlit 侧边栏选择正确的 UE 工作区；
2. 选择已经测试通过的决策模型；
3. 打开“资源注册表”页；
4. 点击“读取 UE 并生成报告”；
5. UnrealMCP 返回资产清单，系统将其折叠为文件夹树；
6. 决策模型按大文件夹、子文件夹直到末级文件夹分析用途和类型；
7. 查看生成的报告，不需要逐个资产确认；
8. 如有误判，在修订意见中说明正确用途并重新生成或修订；
9. 点击“批准报告并建立注册表”。

批准后的报告会同时保存到：

- LCAgent 工作区数据目录；
- UE 工程根目录下的 `.lcagent/resource_registry_report.json`；
- UE 工程根目录下的 `.lcagent/resource_registry_report.md`；
- 当前工作区的对话上下文记录。

任务执行时，模型看到的是经过批准的文件夹语义和由 UE 扫描得到的真实资产路径，不能自行编造资源路径。

### 7.3 更新注册表

用户在 UE 中新增、删除、移动或重命名资产后：

1. 保存 UE 工程和相关资产；
2. 回到“资源注册表”页；
3. 点击“更新注册表”；
4. 检查新增、删除、移动和未变化部分；
5. 审核新的文件夹用途报告；
6. 再次批准。

不要在未经更新的注册表上长期执行真实 UE 操作，否则资产路径可能已经失效。

## 8. 建立文档知识库

知识库用于保存用户主动提供的领域知识、UE 使用说明和场景构建规范。当前支持：

- PDF（可提取文本的 PDF）；
- DOCX；
- TXT；
- Markdown。

扫描版 PDF 需要先进行 OCR，否则可能无法提取有效内容。

### 8.1 创建和导入

1. 先在 Streamlit 中配置并测试默认 Embedding；
2. 在 Electron 侧边栏选择目标工作区；
3. 打开 Electron“知识库”页；
4. 输入知识库名称并创建；
5. 上传文档；
6. 点击导入/建立索引；
7. 等待文本提取、切片和向量写入完成；
8. 使用“检索知识库”输入一个文档中明确存在的问题进行验证。

切片会保留来源文件、页码或段落位置等引用信息。决策智能体需要知识时调用检索工具，检索不到时应明确说明，不应伪造知识来源。

Electron 支持一次选择多个文档，按顺序完成解析和向量入库；单个文件上限为 50 MiB。上传过程需要保持 Embedding API 可用。

### 8.2 Embedding 变更

向量索引与建立它的 Embedding 档案绑定。如果更换模型、服务商或向量维度，旧切片不能直接与新查询向量混用，需要重新导入或重建索引。

## 9. 工作区对话与上下文压缩

### 9.1 对话

1. 在 Electron 中选择工作区；
2. 从模型下拉框选择对话/决策模型；
3. 在底部输入框发送消息；
4. 等待时界面显示加载状态；
5. 回复和用户消息会在独立滚动区中显示，输入框保持在底部。

工作区对话只会获得系统明确提供的工程信息和检索结果，不会自动把整个磁盘目录发送给模型。

### 9.2 自动压缩

每次调用前，系统估算系统提示、历史摘要、近期消息、工作区上下文和本轮输入的 Token 数。达到模型档案中的压缩阈值后：

1. 保留设定数量的最近对话；
2. 将更早内容压缩为结构化摘要；
3. 用摘要替换旧消息；
4. 保存压缩快照；
5. 继续当前模型调用。

若模型 API 调用失败，原始对话不会因为一次失败的压缩而被静默删除。长任务开始前仍建议让模型复述目标、约束和当前阶段，以便人工确认。

对话标题栏中的“压缩上下文”可以提前执行一次强制压缩。历史较短时系统会提示无需压缩。“删除对话”会删除当前工作区的全部原始消息和压缩摘要，且不可恢复，但不会影响其他工作区。

## 10. 运行智能体任务

当前任务执行采用显式状态机：

```text
理解请求 → 检索知识/上下文/资源 → 生成 Python 与 JSON → 校验 → 等待批准 → 执行 → 复核
```

其中只有一个决策大模型。它负责任务规划和生成代码；知识检索、资源解析、JSON Schema 校验、审批和执行由确定性模块完成。

### 10.1 目标草案、审核与冻结

写入场景前，系统先把自然语言需求编译为 `SceneGoalSpec` 草案。草案明确列出：

- 目标实体以及用于定位 Actor 的选择器；
- 必须满足和可选满足的约束；
- 每条约束所需的观测字段；
- 受保护、不得被意外修改的实体；
- 允许使用的资源、容差和可选领域扩展。

模型生成的内容始终是 `draft`，不能自行变成已批准状态。用户查看或修改草案后，客户端应提交当前 `draft_hash` 进行批准；如果草案在审核后发生变化，批准会因哈希冲突被拒绝。批准后的目标被冻结，不能再被草案覆盖。

首个离线样例是 Actor X 坐标约束：`transform.location.x` 必须落在指定范围内。系统会从该约束确定性生成只包含 `identity` 和 `transform` 的查询计划，而不是让模型自行猜测需要查询哪些字段。如果 UE 能力声明缺少 `transform` 或不支持可靠分页，预检会明确返回不可观测，不会填入伪默认值。

Electron“任务”页已经提供可视化审核面板。输入自然语言目标后，先生成草案；可以直接检查和编辑 JSON，使用“校验并保存”重新运行 Schema 与语义检查，再使用“审核并冻结”。冻结后编辑器转为只读，可以生成确定性观测计划。

对应的本地接口为：

| 接口 | 用途 |
|---|---|
| `POST /api/goals/draft` | 调用当前决策模型生成草案 |
| `POST /api/goals/save` | 保存用户编辑或外部导入的结构化草案 |
| `GET /api/workspaces/{workspace_id}/goals` | 列出工作区目标 |
| `GET /api/goals/{goal_id}?workspace_id=...` | 读取目标详情 |
| `POST /api/goals/{goal_id}/approve` | 使用 `expected_draft_hash` 批准并冻结 |
| `POST /api/goals/{goal_id}/observation-plan` | 生成并保存确定性观测计划 |

当前真实强验证执行按钮尚未开放，因为 UE 插件还没有实现通用 `query_scene_state`。这不是模型或客户端故障：离线 Fake UE 闭环已经完成，接入真实 UE 前必须先保证查询支持字段投影、分页、完整性和稳定实体 ID，避免把缺失数据误判为成功。

### 10.2 运行记录和取消

新任务通过持久化运行系统执行。创建任务后会立即获得 `run_id`，服务在后台运行，客户端可以据此查询：

- 当前状态：`queued`、`running`、`repairing`、`succeeded`、`failed` 或 `cancelled`；
- 连续递增的事件序号和当前阶段；
- dry-run/live 模式与运行预算；
- 最终终止原因、模型步数和错误摘要；
- 生成的轨迹产物及其哈希。

取消是协作式取消：已经发出的单次模型请求不会被强制破坏，但请求返回后不会再执行模型给出的动作；已经开始的工具调用完成后，也不会继续下一步。旧 `/api/tasks` 接口仍会同步等待结果，新客户端应使用 `/api/runs` 创建后台任务。

Electron“任务”页可选择任意历史运行，查看按序号保存的事件和 JSON 产物。点击产物名称可直接检查 `SceneGoalSpec`、观测计划、快照、验证报告、差异和修复范围。点击“导出运行包”会在以下位置生成 ZIP：

```text
.lca_data/runs/<run_id>/exports/<run_id>.zip
```

ZIP 包含 `run.json`、`events.jsonl`、`artifacts/` 以及 `manifest.json`。清单记录每个文件的字节数和 SHA-256，常见密钥字段会在落盘和导出前脱敏。

### 10.3 Dry-run

第一次尝试新能力时应使用 Dry-run：

- 生成 Python 脚本；
- 生成要发送给 UE 的 JSON；
- 校验协议版本、命令、字段类型和资源路径；
- 不向 UE 发送执行命令。

先检查生成物，再考虑真实执行。地形、道路和河流能力应分别完成自己的垂直链路测试。

### 10.4 Live 执行

只有在以下条件全部满足时再执行：

- UE 握手成功；
- 目标能力出现在能力清单中；
- 资源注册表是最新且已批准的；
- JSON Schema 校验通过；
- 用户已经明确批准当前计划；
- UE 工程已有可恢复的版本或备份。

## 12. 常见问题

### 12.1 Electron 启动时报 `Electron failed to install correctly`

```powershell
cd E:\LCAgent\desktop
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
node .\node_modules\electron\install.js
Test-Path .\node_modules\electron\dist\electron.exe
```

返回 `True` 后重新运行 `npx --yes pnpm@11.19.0 dev`。

### 12.2 `pnpm` 不是内部或外部命令

无需全局安装 pnpm，直接使用：

```powershell
npx --yes pnpm@11.19.0 install
npx --yes pnpm@11.19.0 dev
```

### 12.3 Python 服务启动失败

先验证环境：

```powershell
E:\LCAgent\langchain_env\Scripts\python.exe -c "import streamlit, langchain_core; print('OK')"
```

如果虚拟环境不在默认位置，启动 Electron 前设置：

```powershell
$env:LCAGENT_PYTHON = "D:\你的环境\Scripts\python.exe"
```

### 12.4 自动获取模型列表失败

确认 Base URL、API Key、代理和厂商 `/models` 接口权限。不能自动发现时，直接填写官方模型 ID并使用“测试连接”验证。

### 12.5 知识库无法检索

确认 Embedding 已测试通过、文档提取到了文本、当前选择的是建立索引时使用的同一个 Embedding 档案。更换模型或维度后需要重建索引。

### 12.6 UE 扫描失败

资源扫描不是离线功能。必须打开 UE、加载 UnrealMCP、握手成功，并确认当前工作区对应正在运行的 UE 工程。
